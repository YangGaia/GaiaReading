# 数据、备份与维护

## 数据位置

公开便携版默认使用 EXE 同级的 `数据` 文件夹，保存书架、进度、偏好、AI 档案及应用可控缓存；迁移时将 EXE 与该文件夹一起移动。源码运行默认使用源码目录同级的 `数据`，测试应显式指定独立 F 盘档案。当前目录式程序与源码的开发约束见 [启动说明](LOCAL_SETUP.md)。

## 完整备份与恢复

关闭阅读器后，备份整个 `数据` 文件夹，包括隐藏文件和子目录。完整备份应保留：

- `GaiaReading_Lucky.json`：书架、进度和偏好等状态。
- `GaiaReading_Lucky-ai-key.bin`：Windows 加密的密钥数据。
- `Local State`：恢复加密资料所需的应用状态。
- 其他配置、存储文件与子目录。

先逐文件核对新备份的路径、大小和 SHA-256，再轮换旧备份。可保留一个已验证的基准备份和最近两份常规备份；应用自己的 `backups` 最多保留五份升级快照，独立于完整备份管理。

恢复前关闭阅读器，保留当前资料的备份，再恢复完整目录。Windows 加密密钥通常绑定原 Windows 用户和机器；迁移到其他环境后可能需要重新填写 API Key。不要把数据备份、状态 JSON、密钥文件或 `Local State` 放入公开仓库或 Release 附件。

## 开发缓存

先在源码目录执行 `. ./scripts/dev-env.ps1`。下列命令只清理源码内 `.cache` 和 `.tmp` 的内容，保留容器目录；执行前关闭阅读器、浏览器验证和其他开发进程。

```powershell
npm.cmd run clean:cache
npm.cmd run clean:cache -- --apply
```

第一条仅预览，第二条才删除缓存。脚本遇到目录连接、变更或占用会停止。`node_modules` 可重新安装；正式源码、测试、文档、图标、字体、图片与音乐素材应保留。完整测试和构建所需的音频见 [音乐素材说明](../assets/bgm/README.md)。

开发检查见 [开发说明](DEVELOPMENT.md)，源码与 EXE 的公开发布检查见 [发布指南](GITHUB_RELEASE.md)。
